# 能力降级矩阵（按需读取）

> 何时读：出现任一能力缺失时（无 Node、无 DOCX、无网络、无法提问…），只读命中的那一行。
> 读完产出：该缺失能力下的降级动作与交付口径（"条件通过"必须写明缺了什么）。
> 总原则见 `SKILL.md`「规则卡」第 8 条「能力降级仍要完成」，不得停在半路。

## 一、缺失能力与降级行为

| 缺失能力 | 降级行为 |
|---|---|
| 无法提问 | 输出问题清单 + 骨架 + 假设清单，记"条件通过"，继续 S2 |
| 无法写文件 | 记忆块与交付物直接输出到对话 |
| 无 Node/脚本 | 用 `05-format.md` 勾选表手工核对；占位符人工扫描并记录 |
| 无 DOCX 或无法读取 docx | G4b 记"无法判定·降级"，交付文本 + 版式未核清单 |
| `scripts/format_docx.js` 不可用（旧包、缺文件、Node 版本过低） | 按上一条降级；不得因缺工具中断交付，也不得声称"已排版" |
| `scripts/export_docx.js` 不可用或导出失败 | 只交文本稿并记"DOCX 未生成·版式未核"；不得声称已出 DOCX，也不得改用其他工具绕过占位清零检查 |
| 用户明确要求只要文字／不要 docx | 交文本稿，注意事项记「版式按用户要求未处理」，G4b 记降级；不反复追问，也不偷偷生成文件 |
| 无 shell | 纯文本运行；不调用脚本 |
| 无网络 | 不引用未核政策；缺依据转占位与待办 |
| 超长文 | 分节 + 已用材料台账 + 断点续写卡 |
| 无提问且门禁二次失败 | 记"升级未遂"，按降级交付并标注风险，不停止 |

## 二、使用纪律

1. 命中即读，不整篇加载；只取对应那一行。
2. 降级结论写进「注意事项」，格式为「缺 X → 采取 Y → 未覆盖 Z」，便于复核。
3. 降级不等于放行：G1/G3/G5 属内容层，缺工具也必须人工完成；只有 G4b 允许记"无法判定·降级"。
4. 不得用降级掩盖占位符未清零、依据未核实；这两项没有降级通道。
