## S0 识别与路由

**输入**：用户请求；若存在记忆目录，读取 `errors.md` 与 `style.md`。

**动作**

1. 解析工作区：用户指定目录优先；否则用当前可写工作目录；**不得把技能包目录当工作区**。记录本次记忆路径。
2. 读记忆：按文种、场景、错误模式关键词匹配，列出命中条目编号；无命中写"无"。记忆只影响警觉点，不改流程。
3. 判任务类型：起草 / 修改 / 审核 / 片段补写。依据用户动词与期望交付物。若请求本质是对已有 `.docx` 做版式处理（无内容改写意图），归入「修改」，风险点记「纯版式改动：只改属性与结构，不改文字」，交付形态记 `+DOCX`。
4. 定文种：按"行文目的 → 行文关系 → 法定适用范围"三步判定，写出判定链。需要完整判定链与场景路由时读 `references/01-routing.md`。
5. 只允许一个文种；出现"请示报告"等混合说法时，按目的拆分或提问。
6. 识别场景（见 `01-routing.md` 第四节场景表）与交付形态（正文 / 正文+版式自检 / +DOCX）。
7. 建任务卡与假设清单（空表）。
8. 判交互能力：可提问 → S1；不可提问 → 输出《信息采集清单》+ 骨架提案 + 假设清单，记"条件通过"并继续 S2，不停止。

**任务卡字段（8 项，全部非空或标假设）**

| 字段 | 内容 |
|---|---|
| 任务类型 | 起草 / 修改 / 审核 / 片段补写 |
| 文种 | 唯一文种 + 三步判定链 |
| 场景 | 场景表定位 |
| 交付形态 | 正文 / 正文+版式自检 / +DOCX |
| 已知信息 | 用户给出的事实、依据、数据 |
| 缺口清单 | 必问项与默认值项 |
| 确认点状态 | 未执行 / 已确认 / 条件通过 / 不适用 |
| 风险点 | 政策、数据、称谓、越权、禁区 |

**假设清单字段**：编号 / 假设内容 / 依据 / 影响范围 / 交付提示。

**检查**：任务卡 8 字段非空或已标假设；文种唯一且合法；假设清单已初始化。

**进入 S1**：任务卡成立。

**回退**：文种无法判定或多文种冲突 → 提一个二选一问题；不能提问时按最可能文种推进，记入假设清单。

## S1 采集与锁定

**输入**：任务卡、假设清单。

**动作**

1. 先读 `references/02-intake.md`。
2. **首轮只问 5 个必问项（P1–P5）**（同一轮问完，不挤牙膏）：①文种与目的；②主送与行文关系（含是否需批复）；③关键事实与数据（含口径、截止时间）；④必须引用的政策原文；⑤明确禁区与"不能动"。
3. **其余维度给默认值**：在询问同一条消息中列"如不修改，按以下默认值执行"，覆盖篇幅、语气、交付形态；用户可一次性改。默认值见 `02-intake.md`。
4. 提供三个逃生口：①你全权决定；②只出稿不问；③我来补材料。
5. 用户选①或②，或环境无提问能力 → **确认点①记"条件通过"**，全部未确认项写入假设清单，继续 S2；不得因此拒绝产出。
6. 选③ → 等待材料后回 S1 增量补问；已答项不重问，F 级缺口转显式占位。
7. 事实标三态（见"占位与标注"）：`[已核·来源：…]`、`[假设·待确认：…]`、`[未知：…]`。未标注不得进正文。
   - 成文日期、发文字号、签发人等未提供时用受控占位，不得自拟。
8. 生成骨架提案（≤20 行）；修改任务同时产出《诊断表》。
9. 请用户确认骨架（确认点①）。

**确认通过判据**：用户明确表示"同意/可以/按此/没问题"；或选择①/②；或提出修改后再次确认。**沉默不等于通过。**

**产出**：信息卡、事实台账 v1、假设清单、骨架提案；修改任务加《诊断表》。

**检查**：必问项已答或转假设；无"问过=问到"；假设清单完整。

**进入 S2**：确认点①通过或条件通过。

**回退**：用户改方向 → 增量补问。

## S2 蓝图

**输入**：已确认骨架 + 信息卡（修改任务：诊断表）。

**动作**

1. 按文种读 `references/03-patterns.md` 取骨架与填写纪律。
2. 逐节填写蓝图：章节 / 唯一任务 / 核心论点 / 支撑材料（挂台账编号）/ 政策依据（条款+原文）/ 字数配比 / 风险点。
3. 给出总篇幅预算与各节配比；配比之和为 100%，单节偏差不超过 ±20%（经验值）。
4. 请用户确认（确认点②）。**判据同确认点①**：用户明确表示"同意/可以/按此/没问题"，或选①/②；选①/②或不可提问时记"条件通过"，假设入清单。**部分同意**（如"第二节再改"）视为未通过——按用户意见改蓝图后重新确认，不得记"条件通过"。

**任务类型差异**：修改 → 改动蓝图（只列改动点与影响范围）；审核 → 记"不适用（审核豁免）"，直接进入 S4；片段 → 片段蓝图（片段任务、上下文、衔接点、字数）。

**产出**：写作蓝图 / 改动蓝图 / 片段蓝图。

**检查**：每节有唯一任务与支撑；与骨架一致；配比合计 100%，单节偏差 ≤±20%。

**进入 S3**：确认点②通过/条件通过；审核记"不适用"。

**回退**：蓝图变更 → 受影响章节重做；骨架变更 → 回 S1 增量。

## S3 起草

**输入**：蓝图（审核任务：用户来文）。

**动作**

1. 逐节循环：明确唯一任务 → 取支撑材料 → 落写 → 即时校验 → 记录已用材料 → 下一节。
2. 生成即校验：本节任务是否完成；有无无支撑判断、无来源数据、无原文依据；是否命中禁用项；称谓与语气是否一致；序数、标点、数字是否合规；是否与已写章节重复；是否新增材料外的具体安排、频次、督查方式或数据。
3. 落点规则：事实挂台账；政策引用附原文摘录与出处；数据区分定值/截至值/待核，截至值带时间。
4. 执行 `references/06-language.md` 的禁用项与去 AI 味清单。
5. 维护"已用材料清单"与"章节任务单"；校验记录只进台账，不混入正文。

**任务类型差异**：修改 → 只改点名处，逐条对应；审核 → 只读，不写正文，记录问题与锚点；片段 → 只写片段，并检查与前后文衔接。

**产出**：初稿（审核：问题记录）。

**检查**：初稿覆盖蓝图 100% 章节，每节至少一个对应段落；缺节列出编号。审核：材料已读全。

**进入 S4**：初稿完整，或审核材料已读全。

**回退**：缺素材 → S1；结构不通 → S2。

## S4 分层修订

**输入**：初稿（审核：用户来文）。

**动作**

1. 按顺序换帽，每顶帽子是一次独立 pass：只读终稿/来文，不引用起草时的理由与自我评价；输出固定表：门禁 / 结论（通过/不通过/无法判定）/ 锚点 / 证据 / 动作。
2. 顺序固定：G1 文种与行文关系 → G2 事实与数据 → G3 政策依据 → G5 结构 → G6 语言 → G4 格式（G4a 内容层、G4b 版式层）→ G7 交付一致。
3. 每顶帽子按 5–7 项一批执行；每批结束记录"未查项"；不得一次勾完 20 项。
4. 每项结论必须带锚点：成稿内"章节序号 + 段首 6 字"或表格行标；G3 另附外部来源锚点（文件+条款）。
5. 判断型门禁（G1/G3/G5）须写"查了哪些位置、找过哪些反例；未发现时写搜索范围"。
6. 回退规则：**G1 文种或行文关系不成立 → 回 S0 重判**（文种判定在 S0，其余阶段无法修正）；事实/政策/结构缺陷 → 回 S1/S2/S3；G4a/G6 局部缺陷 → 就地修正并复检、记录锚点；G4b 无法核对 → 记"无法判定·降级"并写入版式未核清单；G7 失败 → 回 S4 或 S2，不回 S5。
7. 同一门禁在相邻两轮 S4 均不通过 → 升级用户。**无法升级时**（判据见下）把该门禁结论改记为"**带风险交付**"，按降级规则交付，整包标"待核版"，并在注意事项首行写固定标记：`【带风险交付】未闭阻断项：G× × 条｜升级未遂判据：×｜须在报送前补齐`；逐条列出未闭合的阻断项、影响与补救建议。不得停滞，也不得把该结论改写成"通过"。
   **"无法升级"的三条客观判据（满足任一，须在注意事项注明是哪一条）**：
   ① 用户明确选了逃生口②「只出稿不问」，或③「我来补材料」后材料仍未到位；
   ② 本轮内已向用户提出该问题但**未获任何回复**，且已按降级矩阵继续推进；
   ③ 环境本身无提问能力（触发 `10-degradation.md` 首行）。
   **不得以"用户催得急""用户说了别问"作为判据**——后者若未走逃生口，仍应先提一次问题。
   **豁免不可叠加**：同一份稿最多对 2 个门禁记带风险交付；超过 2 个即判"本稿不具备交付条件"，只交问题清单。
   同门禁累计三次仍不通过，即停止加轮、按带风险交付收口。

**任务类型差异**：审核 → 只出分级意见（必须改/建议改 + 门禁 + 锚点），不改稿；修改 → 对照改动蓝图，只改点名处；片段 → 判定对象是片段本身（G5 衔接、G6 语言、G4a 格式）；G1/G2/G3 只对宿主成稿记建议，不阻片段交付，也不得据此改写宿主。

**产出**：终稿 + 取证表（审核：意见清单）。

**检查**：阻断型门禁无"不通过"，或已按第 7 条改记"带风险交付"并列出未闭项；降级项均已记录；审核意见逐条可定位。

**进入 S5**：满足上述检查。

**回退**：按第 6 条。

## S5 交付

**输入**：终稿 + 取证表（审核：意见清单）。

**交付物（固定两部分，不得混排）**

| 部分 | 内容 | 禁止 |
|---|---|---|
| **正文** | 一个或多个公文文本（按用户要求）；只含公文本身 | 过程说明、假设清单、门禁记录、审核标注、内部元信息 |
| **注意事项** | 待核清单、假设清单、版式未核项、风险提示、修改说明（修改任务）、审核意见（审核任务）、使用说明 | 大段重复正文；与正文编号不对应 |

正文中确需保留缺失信息的，只允许受控占位 `【待补：…】【待核：…】【待核对原文：…】`；每条占位必须在注意事项中有对应编号与处理建议。

**动作**

1. 生成正文：剥离审核标注、假设清单、门禁记录与内部元信息；事实三态与来源迁入取证表；正文只保留公文文本与受控占位。
2. 生成注意事项：逐条列出待核/待补/待核对原文（编号 → 正文位置 → 缺什么 → 建议动作 → 影响）、假设、版式未核项、风险、修改说明/审核意见、使用说明。
3. 扫描正文：运行 `node scripts/check_format.js <正文文件> --json`（支持 .txt/.md/.docx；退出码 0=无残留，1=有残留，2=参数/读取错误）。退出码 1 按 JSON 的 code 区分占位与格式提醒。正文占位清零 → 正式件；未清零 → 整包标注“待核版”，但正文与注意事项仍分开。
4. 按任务卡的交付形态执行：
   - 正文：只做占位、元信息、原话三项检查；
   - 正文+版式自检：读 `references/05-format.md` 核对 G4a；G4b 无 DOCX/人工核对时记“无法判定·降级”，写入注意事项；
   - +DOCX：先完成占位清零，再运行 `node scripts/export_docx.js <正文.md|txt> <输出.docx>`（默认拒绝覆盖，需 `--force`；`--dry-run` 只检查）。DOCX 只导出正文；注意事项不并入 DOCX 正文。导出后按 `05-format.md` 第九节复检 G4a，未通过项写入注意事项。
5. **排版建议（义务）**：满足任一即提一次——交付形态含 `+DOCX`；用户提到用 Word／报送／打印／上会／盖章；存在 G4b 未核项且 `scripts/format_docx.js` 可用。话术与边界见主文件「排版建议与版式处理」一。
   - 用户同意 → 运行 `node scripts/format_docx.js smart <输出.docx> <输出_规范.docx> --force`（需署名时加 `--author 姓名`），把段落类型统计、结构空行数、日期规范化数、元数据清理项写入注意事项；G4b 由「无法判定·降级」改记「机检通过 + 待人工复核项」。
   - 用户拒绝或未表态 → 注意事项记「版式未处理（用户选择／未表态）」，不得默认为同意；本轮不再提。
   - 用户此前已选「只出稿不问」→ 不提，按 `+DOCX` 导出并记版式未核。
6. 用户原话复核：任务卡与确认点是否忠实于用户原话？禁区是否遵守？输出 ≤5 行对照表，放入注意事项。
7. 风险提示并入注意事项，不单列在正文后。

**审核任务**：只交付意见清单与范围/原话复核；不产正文、待办、DOCX。

**产出**：正文（一份或多份）+ 注意事项 [+DOCX]。

**检查**：正文无过程/审核标注/假设清单；所有占位与假设在注意事项有对应条目；正式件无占位；与原话一致。

**进入 S6**：交付完成。

**回退**：复核不一致 → S4 或 S2。

## S6 记忆沉淀

**输入**：全过程 + 用户反馈。

**动作**

1. 提取候选记忆，**每次最多 3 条**：用户明确纠正、门禁退回原因、重复错误、稳定偏好。
2. 先查重：同模式已在库中 → 不新增，改为在原条目追加日期与 `superseded_by`；旧条目保留并标"已合并"。
3. 错误条目用五段式，并附 `confidence`（高/中/低）与来源；政策/格式类条目加 `last_verified`，超过 6 个月标"待复核"。
4. 展示候选，请用户确认后写入；用户明说"直接记"时可直接写入。
5. **用户要求删除/更正时优先执行**：物理删除或脱敏，并记录删除日期、原因、范围。
6. 无候选 → 明确说明"本次无可沉淀条目"并结束，不写空文件。
7. 无法写文件 → 输出《记忆块》。
8. **记忆梦境（固定动作，不可省）**：按 `13-experience.md` 回看"草稿 → 终稿"的全部改动，做通用性四问。四问全过的，写入 `experience/E-NNN-*.md` 并在 `experience/INDEX.md` 加一行；不过的，在本次注意事项写明"哪一问未过"，不得只写"无可沉淀条目"了事。同一模式第二次出现时改原条目的复现次数，不新建文件。

**产出**：更新后的记忆文件或记忆块。

**检查**：只追加不改写（合并用引用）；删除有记录；无正文/密级/个人信息。

## 附：交互契约（完整判据）

- 首轮只问 5 个必问项（P1–P5），同一轮问完；其余给默认值，列"如不修改按默认执行"。
- 三个逃生口固定提供：①你全权决定；②只出稿不问；③我来补材料。
- 选①/②，或环境无提问能力 → 确认点记"条件通过"，假设入清单，继续流程；不得拒绝产出。
- 选③ → 收到材料后回 S1 增量补问，已答项不重问。
- 确认通过 = 明确同意/可以/按此，或选择①/②；沉默不算通过。
- 确认点只有两处：骨架（确认点①）与蓝图（确认点②）。S0 二选一、S4 升级不是确认点。
- 审核任务的确认点①②均记"不适用"（审核不产骨架与蓝图）；片段补写记①"不适用"、②适用（片段蓝图）；修改任务用《诊断表》替代 S1 的常规信息卡。
- 不得假装问过；不得重复问已答项；不得把假设写成事实。
- 除确认点、门禁二次失败升级与 S6 写入确认外，其余自行决断。
