# 格式要素与版式自检（GB/T 9704-2012）

> 何时读：S4-G4 格式门禁；S5 交付前版式自检；涉及要素、字体字号、页码、特殊格式时。
> 读完产出：版式自检表与问题清单。
> 适用边界：国标适用于党政机关公文，其他单位参照执行。纯文本交付只能保证要素齐全与写法正确；字体、字号、页边距需由 DOCX 导出或人工排版落实。
> 性质标注：本文件以国标条文为主；凡属通行做法或编辑惯例，正文标注"惯例"；未标注者为国标条文或直接推导。

## 一、版面

| 项目 | 规定 |
|---|---|
| 纸张 | A4，210 mm × 297 mm |
| 天头（上白边） | 37 mm ± 1 mm |
| 订口（左白边） | 28 mm ± 1 mm |
| 版心 | 156 mm × 225 mm（不含页码） |
| 每面行数 | 一般 22 行 |
| 每行字数 | 一般 28 字，撑满版心 |
| 默认字体字号 | 无特殊说明时为 3 号仿宋 |
| 文字颜色 | 黑色 |
| 印制 | 双面印刷，左侧装订 |

下白边约 35 mm、右白边约 26 mm 为换算值，国标未直接规定，不作为验收硬项。

## 二、版头要素

| 要素 | 编排 | 字体字号 |
|---|---|---|
| 份号 | 如需标注，顶格编排在版心左上角第一行 | 6 位 3 号阿拉伯数字 |
| 密级和保密期限 | 如需标注，顶格编排在版心左上角第二行；保密期限用阿拉伯数字 | 3 号黑体 |
| 紧急程度 | 如需标注，顶格编排在版心左上角；与份号、密级同时标注时按"份号→密级→紧急程度"分行 | 3 号黑体 |
| 发文机关标志 | 机关全称或规范化简称加"文件"，也可只用全称/简称；居中，上边缘至版心上边缘 35 mm（**下行文／平行文**）；联合行文主办机关在前 | 推荐小标宋体，红色 |
| 上行文留位 | 上行文须标注签发人（《条例》第九条第六项），发文机关标志以下须留出签发人位置，故其垂直位置与下行文不同；**具体数值以 GB/T 9704-2012 7.2.2 原文为准，本表不臆造** | — |
| 发文字号 | 发文机关标志下空二行，居中；年份用六角括号〔〕，顺序号不编虚位、不加"第"、后加"号"；**上行文发文字号居左空一字，与最后一个签发人姓名同一行** | 3 号仿宋 |
| 签发人 | "签发人："三字加全角冒号和姓名，**整体居右空一字**；多个签发人按发文机关顺序从左到右、自上而下均匀编排，一般每行两个姓名，回行与上一行第一个姓名对齐 | "签发人"3 号仿宋，姓名 3 号楷体 |
| 版头分隔线 | 发文字号之下 4 mm，居中，与版心等宽 | 红色 |

## 三、主体要素

| 要素 | 编排 | 字体字号 |
|---|---|---|
| 标题 | 红色分隔线下空二行，居中，回行词意完整、排列对称，用梯形或菱形；**标题中除法规、规章名称加书名号外，一般不用标点；顿号、引号、括号等确需时可用，避免句号、感叹号** | 一般 2 号小标宋 |
| 主送机关 | 标题下空一行，居左顶格，回行顶格，末尾全角冒号；主送过多致首页无正文时移至版记 | 3 号仿宋 |
| 正文 | 首页必须显示正文；主送机关下一行，每段左空二字，回行顶格 | 3 号仿宋 |
| 附件说明 | 正文下空一行左空二字，"附件："加名称；多个附件用"1. "标序；名称后不加标点；回行与名称首字对齐 | 3 号仿宋 |
| 发文机关署名 | 用全称或规范化简称 | 3 号仿宋 |
| 成文日期 | 署名下一行；用阿拉伯数字标全年月日，月日不编虚位；盖章情形一般右空四字 | 3 号仿宋（数字） |
| 印章 | 红色，端正居中下压署名和成文日期，不得空白印章；顶端上距正文（或附件说明）一行之内 | — |
| 附注 | 成文日期下一行，居左空二字，加圆括号 | 3 号仿宋 |
| 附件 | 另面编排，位于版记之前，与正文一起装订；"附件"及序号顶格编排在版心左上角第一行，附件标题居中在版心第三行 | "附件"及序号 3 号黑体；附件正文同正文 |

### 署名、日期与印章的三种情形

1. **加盖印章**：单一机关行文，署名以成文日期为准居中，印章下压署名与日期；联合行文各机关署名依次排列，印章一一对应，互不相交或相切。
2. **不加盖印章**：正文（或附件说明）下空一行，右空二字编排署名，署名下一行编排成文日期，日期首字比署名首字右移二字。
3. **加盖签发人签名章**：正文下空二行右空四字加盖签名章，签名章左空二字标注签发人职务，签名章下空一行右空四字编排成文日期。

空白处容不下印章或日期时，调整行距、字距解决；2012 版通常不再标注"此页无正文"（惯例）。

## 四、版记与页码

| 要素 | 规则 | 字体字号 |
|---|---|---|
| 抄送机关 | 左右各空一字；"抄送："加名称，回行与冒号后首字对齐，末尾用句号；主送移至版记时改标"主送" | 4 号仿宋 |
| 印发机关和印发日期 | 末条分隔线之上，印发机关左空一字、印发日期右空一字；日期用阿拉伯数字，后加"印发" | 4 号仿宋 |
| 版记分隔线 | 与版心等宽；首条、末条用粗线（推荐 0.35 mm），中间用细线（推荐 0.25 mm）；末条与版心下边缘重合 | — |
| 页码 | 版心下边缘之下，数字左右各一条一字线，一字线上距版心下边缘 7 mm；单页码居右空一字，双页码居左空一字；版记页前的空白页与版记页不编页码；附件与正文一起装订时页码连续 | 4 号半角宋体 |

## 五、层次序数与字体

| 层级 | 序数 | 序数后标点 | 字体 |
|---|---|---|---|
| 第一层 | 一、 | 顿号 | 黑体 |
| 第二层 | （一） | 不加标点 | 楷体 |
| 第三层 | 1. | 下脚点（齐线墨点） | 仿宋 |
| 第四层 | （1） | 不加标点 | 仿宋 |

- 不跳级、不混用；"（一）""（1）"后不加顿号或点。
- 第三层用半角下脚点，不写"1、"。
- 一般不超过四层；超过时按本机关惯例改用"一是/二是"或分段（惯例）。

## 六、日期、文号与数字

- 成文日期：`2026年11月15日`（阿拉伯数字，月日不编虚位）。
- 发文字号：`××〔2026〕1号`（六角括号、年份全称、顺序号不编虚位、不加"第"）。
- 数字用法：统计数字、日期、文号用阿拉伯数字；相邻数字并列连用的概数用汉字，其他概数按 GB/T 15835 处理。
- 数值范围可用"至"、一字线"—"或浪纹号"～"（GB/T 15835 允许）；同一文内统一，避免混用。
- 计量单位用法定单位（GB 3100～3102）。
- 标点按 GB/T 15834；标题标点见第三节。

## 七、特殊格式

### 信函格式

| 要素 | 规则 |
|---|---|
| 发文机关标志 | 机关全称或规范化简称，居中，上边缘至上页边 30 mm；联合行文用主办机关标志 |
| 红色双线 | 标志下 4 mm 印一条红色双线（上粗下细）；距下页边 20 mm 处印一条红色双线（上细下粗）；线长均 170 mm，居中 |
| 份号、密级、紧急程度 | 顶格居版心左边缘，编排在第一条红色双线下；第一个要素与线相距 3 号汉字高度的 7/8 |
| 发文字号 | **顶格居版心右边缘**，编排在第一条红色双线下（信函不适用 7.2.5 的居中规则） |
| 标题 | 居中，与其上最后一个要素相距二行 |
| 第二条红线 | 上一行如有文字，距线为 3 号汉字高度的 7/8 |
| 页码 | 首页不显示页码 |
| 版记 | 不加印发机关和印发日期、分隔线，位于最后一面版心内最下方 |

### 命令（令）格式

- 发文机关标志由机关全称加"命令"或"令"字组成，上边缘至版心上边缘 20 mm。
- **标志下空二行居中编排令号，令号下空二行编排正文。**
- 签发人职务、签名章与成文日期按签名章情形编排。

### 纪要格式

- "×××纪要"标志，上边缘至版心上边缘 35 mm。
- **在正文或附件说明下空一行左空二字编排"出席"二字**，后标全角冒号；冒号后用 3 号仿宋标注单位、姓名，回行与冒号后首字对齐；请假、列席另起一行。
- 格式可按实际制定；通常不盖章（惯例）。

## 八、2012 版避坑

- 成文日期用阿拉伯数字，不用汉字（"二〇二六年"是旧规）。
- 已取消主题词。
- 统一署发文机关名称。
- 法定文种为 15 种（含决议、公报，"会议纪要"改称"纪要"）。
- 版头不称"眉首"。
- 22 行 28 字是国标原文；行距磅值只是软件换算，不得写成"国标规定行距 28 磅"。
- 网传"新版国标"（如 2025/2026 版）系误标，现行仍为 GB/T 9704-2012（2025-05-30 复审继续有效）。

**脚本边界**：版头（份号／密级／紧急程度／发文机关标志／发文字号位置／签发人）与版记（抄送机关位置／印发机关及日期／分隔线）不由 `scripts/` 生成，相关自检项须**人工核对**；脚本只处理正文层面（页面几何、字体字号、行距、缩进、结构空行、页码、元数据）。要素检查按文种分流（v0.8.1）：`check_format.js --type <文体>`；公布性文种、决议、命令、纪要不要求主送，纪要与事务材料不要求成文日期，事务材料不要求标题含法定文种名。不传 `--type` 时按标题推断，推断不出仍按法定公文口径从严。据此类推，`preset.js` 无 signer 类型、无版记部件，不代表规则有误。

说明：G4 分两层。G4a 内容层（序数、日期、文号、要素齐全、标点）必须通过；G4b 版式层（字体、字号、页边距、印章、页码）由 S5 排版工序的 `analyze` 复检出结论（v0.8.0 起起草/修改固定执行），仅五种例外可记“无法判定·降级”，写入版式未核清单，不计通过但不阻断交付。占位与标注语法见 SKILL.md《占位与标注》；正式件导出前占位符必须清零，未清零仍可导出但只能标「待核版」。

## 十、输出模板（v0.3.0 从 SKILL.md 迁入）

> 权威出处：本节即 v0.2.1 主文件第 335–345 行。

**正文文件**：`<文种>_<事由>_<日期>_正文.md`（多份时加 `_1`、`_2`）。只含：标题 → 主送机关 → 正文（层级序数）→ 附件说明 → 发文机关署名 → 成文日期。版式以本文件第九节为准；不混入过程、假设、审核标注。

**注意事项文件**：`<文种>_<事由>_<日期>_注意事项.md`，固定包含：

- 待核清单：`A1｜正文第2节第3段｜数据待核｜补2026年三季度值｜影响：资金测算`
- 假设清单：`H1｜主送按“各区县人民政府”处理｜依据：用户口径｜影响：称谓与分送范围`
- 版式未核项：`P1｜字体字号｜需人工核对｜影响：正式件外观`
- 风险提示：`[假设·待确认] 1 项；【待核】2 项；【版式未核】1 项`
- 修改说明（修改任务）：`原：… → 改：…｜依据：G6 禁用项`
- 审核意见（审核任务）：`【必须改】G1｜主送栏｜…`
- 使用说明：`正文中【待核】处需补齐后方可作为正式件`

## 十一、机检码速查（看到码就知道改哪里）

`check_format.js` 与 `format_docx.js analyze` 的 `code` 共 70+ 个，下表按"会不会改变修订动作"筛选，同族码合并成一行（如 `DATE_*`、`DOC_NO_*`、`SERIAL_*`）；未列出的码看 `message` 即可。
