## 使用

由 `SKILL.md` frontmatter 的 `description` 触发；新会话中说「用公文笔正起草一份通知」即可。脚本需 Node（本机已验证 22.12.0）：

```bash
node scripts/check_format.js <正文.md|txt|docx> --json       # 退出码 0 通过 / 1 有项 / 2 错误
node scripts/export_docx.js <净稿.md|txt> <输出.docx> --dry-run
node scripts/export_docx.js <净稿.md|txt> <输出.docx> --force
node scripts/format_docx.js analyze <来文.docx> --json        # 只读诊断，不改文件
node scripts/format_docx.js smart <来文.docx> <出.docx> --author 张三 --force
```

`export_docx.js` 与 `format_docx.js` 默认拒绝覆盖已有输出；`--dry-run` 只解析不写文件。三个脚本仅使用 Node 内置模块，无网络访问、无删除操作。

> **v0.4.1 起导出与排版同源**：`export_docx.js` 不再自带字体字号常量，改为先出骨架包、再走 `docformat` 管线（`preset` 定参数、`detect` 定段落类型、`ppr` 装配属性）。因此导出产物与 `format_docx.js smart` 产物版式一致，`analyze` 对导出产物应为 0 阻断项。
> 随之而来的行为变化：Markdown 的 `##`/`###` 只用于剥离标记，不再决定字体——层次标题按公文层次序数（一、／（一）／1.）判定，与 `analyze` 判据同一套。

## 版式能力（v0.4.0 新增）

补齐 G4b 的执行侧：既能**看**到一份已有 docx 的真实版式，也能**改**它。

| 模式 | 作用 | 是否写文件 |
|---|---|---|
| `analyze` | 只读诊断：页边距、字体字号、行距、缩进对齐、要素齐全、文字层序数与日期、元数据痕迹 | 否 |
| `format` | 只修版式：页面几何、段落识别与套版、结构空行、页码、日期写法、媒体段保护 | 是（新文件） |
| `meta` | 只清元数据 | 是（新文件） |
| `smart` | `format` + `meta`（推荐） | 是（新文件） |

**只改版式，不改文字**：标点全角化、`1、`→`1.`、措辞调整一律不做，诊断模式只报不改。这保证与原硬约束「只改点名处」一致。

**元数据清理口径**（只清「暴露由程序或 AI 生成」的痕迹）：

| 清除 | 保留 |
|---|---|
| `creator` / `lastModifiedBy` 中的生成器签名（python-docx、LibreOffice、Pandoc 等） | `Template=Normal.dotm`、空的 `Company`/`Manager` |
| `description` 含 `generated by` 或 AI 工具自述 | 真实作者名（不在签名库内） |
| 模板假时间（如 `2013-12-23T23:15:00Z`）、创建与修改时间完全相同 | 批注、修订、域代码（属内容非元数据） |
| `Application` 与实际平台矛盾、`TotalTime=0`、字数统计全 0 | 文档样式、主题、字体表 |
| `docProps/thumbnail.jpeg` 模板缩略图、`rsid` 编辑会话标记 | 文档正文与结构 |

作者字段默认**清空而非代填**；需署名时用 `--author 姓名` 显式指定。源文件若缺 `docProps`（部分自研导出脚本如此），会自动补齐合理的 `core.xml` + `app.xml`。

**已知边界**：不处理 `.doc`/`.wps`（需 Office/WPS 的 COM）；不做版头、版记、印章；不做修订痕迹与表格智能对齐。机检覆盖页边距、字体字号、行距、缩进对齐、结构空行、要素齐全、文字层序数与日期、文档属性痕迹；**不覆盖页码、印章、版头与版记**，这几项须人工核对或记降级。

**读取侧防护（v0.4.2 起）**：逐条目校验 CRC-32（不匹配即报错，不再静默解出错误内容）；单条目解压上限 256 MB；ZIP64 格式显式拒绝并提示另存。输出路径与输入文件相同时一律拒绝（含 `--force`），不做原地覆盖。`check_format.js` 自 v0.4.4 起与 `format_docx.js` 共用同一读取器，不再各写一套。

**OOXML 覆盖度声明**：脚本按片段正则处理 OOXML，不做完整 DOM 解析。已支持正文段落、表格、图片与媒体部件、分节符、自动编号、样式引用、制表位、域代码；**不支持**嵌套同名 `<w:p>`（部分表格特殊结构）、文本框内段落重排、修订痕迹合并、CDATA 内文本识别。不支持的构造以「不崩溃且输出良构」为底线，语义保真须人工核对。

**运行时要求**：Node >= 18（`package.json` 的 `engines` 已声明）。低于该版本可能在解压参数与正则特性上静默降级。

**与同类项目的关系**：版式参数取自 GB/T 9704-2012 与公文排版通例。实现参考了 `KaguraNanaga/docformat-gui` 的功能取舍，但**未复制其 v1.8.8.3+（PolyForm Noncommercial）代码、注释或常量表**，为独立重写，故本包不含该许可的衍生作品。该项目的 MIT 版本（`document-format-skills`）与本包思路相近，此处一并致谢。

## 记忆梦境（v0.6.0 新增）

写完之后不立刻收工：回看「草稿 → 终稿」的全部改动，把可复用的判断提炼成经验条目，长期抬高这个技能的水平。

```
每次交付完成（S6 之前，固定动作）
  → 回看改动：这次哪里改得最多、为什么
  → 通用性四问：可脱离本篇？可判定？非孤例？有出处？
  → 四问全过 → 写入 experience/E-NNN-主题.md + INDEX.md 加索引
  → 任一不过 → 只进本次《注意事项》，写明哪一问未过
```

**门槛与拒收**：四问全「是」才入库；具体数据、单位名、人名、一次性偏好、涉密信息、无判据的「感觉」一律不收（见 `references/13-experience.md` 三、四节）。

**晋升**：复现 2 次升「高」并合并；复现 3 次以上且与国标一致，**提请**用户同意后才写入 `references/`；12 个月未复现标「待复核」。经验库不得覆盖硬规则，冲突时以 `07-review.md` 为准。

> ⚠️ **`experience/` 是你个人的本地资产，不属于技能包**：不进 git、不进 `release-*` 快照、不随技能分发。**重装或覆盖升级前请先备份该目录**，否则升级会连同技能目录一起替换。
